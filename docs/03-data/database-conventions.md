# Database Conventions

> **Status:** Accepted · **Owner:** Data Platform · **Version:** 2.0
>
> These rules apply to every service schema. A schema that violates them fails review. The goal is a
> database that is predictable, auditable, tenant-safe and fast under load.

## 1. Naming

| Object | Convention | Example |
|---|---|---|
| Schema | singular domain | `student` |
| Table | plural `snake_case` | `student_guardians` |
| Column | singular `snake_case` | `effective_from` |
| Primary key | `id` | `id uuid` |
| Foreign key | `<entity>_id` | `student_id` |
| Boolean | `is_` / `has_` / `can_` | `is_primary` |
| Timestamp | `<verb>_at` | `created_at`, `published_at` |
| Date | `<noun>_on` or `<noun>_date` | `starts_on`, `due_date` |
| Money | `<noun>_amount` + `currency` | `total_amount`, `currency` |
| Constraint | `ck_`, `uq_`, `fk_`, `ix_` | `uq_enrolment_active` |
| Index | `ix_<table>_<cols>` | `ix_enrolments_tenant_section` |
| Partition | `<table>_<range>` | `attendance_records_2026_09` |

Reserved words are never used as identifiers. Abbreviations are avoided except `id`, `url`, `ip`.

## 2. Keys and identifiers

- Primary key: `id uuid` generated by the application as **UUIDv7** (time-ordered, index-friendly).
- No natural keys as PKs (email/student number can change); use unique constraints instead.
- Human-readable numbers (`student_number`, `invoice_no`) are separate, unique per scope, and
  immutable once issued.
- Cross-service references are opaque UUIDs; **no cross-schema foreign keys**.
- Within a schema, foreign keys are mandatory for owned relationships.
- Composite unique constraints include `tenant_id` first.

```sql
create table student.enrolments (
  id              uuid primary key,
  tenant_id       uuid not null,
  student_id      uuid not null references student.students (id),
  section_id      uuid not null,
  term_id         uuid not null,
  status          text not null,
  effective_from  date not null,
  effective_to    date,
  version         integer not null default 1,
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now(),
  created_by      uuid not null,
  updated_by      uuid not null,
  constraint ck_enrolment_dates check (effective_to is null or effective_to > effective_from)
);
```

## 3. Standard columns

Every mutable business table has:

| Column | Type | Rule |
|---|---|---|
| `id` | `uuid` | PK, UUIDv7 |
| `tenant_id` | `uuid` | NOT NULL; first column of every index |
| `created_at` | `timestamptz` | NOT NULL, default `now()` |
| `updated_at` | `timestamptz` | NOT NULL, default `now()` |
| `created_by` | `uuid` | NOT NULL (system actor for jobs) |
| `updated_by` | `uuid` | NOT NULL |
| `version` | `integer` | NOT NULL default 1; optimistic concurrency |
| `deleted_at` | `timestamptz` | Nullable; soft delete where applicable |

Append-only tables (ledger, audit, payment events) omit `updated_*`, `version`, `deleted_at`; they
are immutable by design.

## 4. Types

| Concept | Type | Notes |
|---|---|---|
| Identifier | `uuid` | UUIDv7; never serial/int for business IDs |
| Short text | `text` | PostgreSQL `text` + CHECK; avoid arbitrary `varchar(n)` |
| Long text | `text` | Separate table if large/frequently updated |
| Money | `numeric(19,4)` | Pair with `char(3)` ISO currency; never float |
| Quantity | `numeric(19,4)` | Or integer when unit is indivisible |
| Percentage | `numeric(7,4)` | 0–100 with CHECK |
| Date | `date` | Calendar dates (terms, due dates) |
| Timestamp | `timestamptz` | Always UTC; display in institution timezone |
| Time of day | `time` | Rare; prefer timestamps for events |
| Duration | `interval` | Or integer minutes for policy |
| Boolean | `boolean` | NOT NULL + default |
| Enum-like | `text` + CHECK | Avoid PG enums for evolvability |
| JSON | `jsonb` | Config/schemaless only; validated by Zod |
| Array | `text[]`/`uuid[]` | Only for small, immutable sets |
| Hash | `bytea`/`text` | SHA-256 hex or base64; document algorithm |
| Encrypted | `bytea` | AES-256-GCM ciphertext + key version |

Rules:

- No `timestamp` without timezone.
- No `money`/`float` for currency.
- No `char(n)` for variable text.
- `null` means unknown/not applicable; do not use sentinel values (`''`, `0`, `'1900-01-01'`).
- Booleans are `is_*` and NOT NULL.
- Store `currency` alongside every amount; a table is single-currency per row, not per column.

## 5. Constraints

- `NOT NULL` by default; nullable only with a documented meaning.
- `CHECK` for domain invariants that are local (`amount > 0`, `ends_on > starts_on`).
- `UNIQUE` for business keys, scoped by tenant.
- `FOREIGN KEY` within the schema; `ON DELETE RESTRICT` by default, `CASCADE` only for owned
  child records with no independent meaning.
- Exclusion constraints for non-overlapping periods (enrolment, contracts, bed allocation).
- Deferred constraints for balanced journals only when necessary.

```sql
-- One active enrolment per learner per section/term
create unique index uq_enrolment_active
  on student.enrolments (tenant_id, student_id, section_id, term_id)
  where status = 'active' and deleted_at is null;

-- No overlapping active bed allocations
alter table hostel.allocations
  add constraint ex_bed_allocation_overlap
  exclude using gist (
    bed_id with =,
    daterange(effective_from, effective_to, '[]') with &&
  ) where (status = 'active');
```

## 6. Row-level security

Every tenant-scoped table:

```sql
alter table student.students enable row level security;
alter table student.students force row level security;

create policy students_tenant_isolation on student.students
  using (tenant_id = current_setting('app.tenant_id', true)::uuid)
  with check (tenant_id = current_setting('app.tenant_id', true)::uuid);
```

- Runtime role has no `BYPASSRLS`.
- Missing `app.tenant_id` must raise, not return all rows.
- Every query also has explicit `tenant_id = $1`.
- Migrations/backfills use a separate role and are audited.
- RLS is tested with two tenants on every migration.

## 7. Indexing

| Rule | Detail |
|---|---|
| Tenant first | Every tenant-scoped index starts with `tenant_id` |
| Selectivity | Index columns used in WHERE/JOIN/ORDER; avoid low-cardinality alone |
| Partial | Index only active/relevant rows (`where deleted_at is null`) |
| Covering | Include columns for hot read paths (`include (...)`) |
| Foreign keys | Index every FK used for joins/lookups |
| Uniqueness | Enforce in DB, not only application |
| Text search | `tsvector` generated column + GIN; trigram for fuzzy |
| JSONB | GIN only for fields actually queried; otherwise don't |
| Avoid | Redundant indexes, indexing every column, functions on indexed columns |

```sql
create index ix_enrolments_tenant_section_active
  on student.enrolments (tenant_id, section_id)
  where status = 'active' and deleted_at is null;
```

## 8. Transactions and concurrency

- Transactions are short; no network calls (PSP, email) inside a transaction.
- Use `READ COMMITTED` by default; `SERIALIZABLE` only with a documented retry policy.
- Optimistic concurrency: `update ... where id=$1 and version=$2`; 0 rows → conflict (409).
- Pessimistic locks: `SELECT ... FOR UPDATE` in a consistent order to avoid deadlocks; retry on
  deadlock/serialization failure.
- Never hold a lock while waiting on a Queue/Workflow.
- Idempotency: unique request key or inbox; retries must be safe.
- Counter/sequence allocation uses a DO or DB sequence; never `max(id)+1`.

```sql
update student.students
set status = $3, version = version + 1, updated_at = now(), updated_by = $4
where id = $1 and tenant_id = $2 and version = $5
returning *;
```

## 9. JSONB policy

JSONB is allowed for:

- Tenant configuration/settings with a versioned schema.
- Custom field values (validated).
- Event payloads/outbox bodies.
- Provider metadata that changes often.

JSONB is **not** allowed for:

- Core financial or grading fields.
- Data that must be queried/joined frequently.
- Anything without a schema and validation.
- PII that is not classified and encrypted.

Rules: validate on write; version the schema; add GIN indexes only for known query paths; keep
payloads small; never store secrets.

## 10. Soft delete and history

- `deleted_at` for entities that must remain recoverable (learner, staff, documents).
- Financial, audit and event records are never soft-deleted; they are immutable.
- Queries must filter `deleted_at is null` unless explicitly historical.
- Unique indexes are partial to allow re-creation after soft delete.
- Hard deletion happens only via retention workflow with legal-hold check.
- History tables (`*_history`) or event sourcing for audited changes; no destructive updates to
  published grades, invoices or journals.

## 11. Audit columns and change capture

- `created_by`/`updated_by` are user or system actor IDs.
- Every sensitive change emits an audit event via outbox with before/after (redacted).
- Financial and grade tables additionally keep immutable versions/snapshots.
- Audit events are append-only, hash-chained and archived to R2 object lock.

## 12. Migrations

### Rules

1. One migration owner: the service team.
2. Migrations run in CI **before** the Worker deploy, never from a request.
3. **Expand → backfill → switch → contract.** Destructive changes in a later release.
4. Backfills are batched, idempotent, resumable and throttled.
5. Index creation uses `CONCURRENTLY` where supported; never lock a hot table for long.
6. Every migration is tested from an empty database and from the previous production schema.
7. Migration files are immutable once applied; fix forward with a new migration.
8. A rollback plan is documented; data-destructive rollbacks are not allowed.

```sql
-- Expand: add nullable column, no default rewrite
alter table student.students add column preferred_name text;

-- Backfill in batches (application job), then:
alter table student.students alter column preferred_name set not null;

-- Contract (next release): drop old column after code stops using it
```

### Drizzle workflow

```bash
pnpm --filter @athena/student-service db:generate   # SQL from schema diff
pnpm --filter @athena/student-service db:migrate    # apply in CI/target env
```

- Review generated SQL; Drizzle Kit does not replace review.
- Never use `db:push` against staging/production.
- Each service has its own `drizzle/` folder and migration journal.
- Migration job uses a dedicated role and records an audit event.

## 13. Query standards

- No `select *` in application code; list columns explicitly.
- Always filter by tenant; always limit result sets.
- Cursor pagination `(created_at, id)`; avoid large OFFSET.
- Avoid N+1; batch/join within the service.
- Use `EXPLAIN (ANALYZE, BUFFERS)` for new hot queries; record plans in the PR.
- Query budget: p95 < 50 ms for OLTP reads; no query > 500 ms without review.
- Reporting queries run on replicas/materialized views, not the primary.
- Full-text search uses `tsvector` + GIN; fuzzy uses `pg_trgm`.
- `LIKE '%...%'` on large tables is banned without a trigram index.

## 14. Encryption and searchable PII

- Application-level AES-256-GCM for restricted fields (health, national ID, bank details).
- Ciphertext column `bytea` + `key_version`; plaintext never logged.
- For exact-match search on encrypted data, store a **blind index**:
  `HMAC-SHA256(tenant_key, normalized_value)` in a separate column with a unique index.
- Do not use deterministic encryption for general fields; it leaks patterns.
- Key rotation re-wraps DEKs; old key versions remain decryptable until re-encrypted.
- Search/analytics never receive plaintext restricted fields.

```sql
create table health.visits (
  id uuid primary key,
  tenant_id uuid not null,
  student_id uuid not null,
  notes_ciphertext bytea not null,
  notes_key_version integer not null,
  created_at timestamptz not null default now()
);
```

## 15. Outbox and inbox (standard tables)

Every service that publishes events has `outbox`; every consumer has `inbox`. See
[Integration & events](../01-architecture/integration-and-events.md) for columns and indexes.
These tables are partitioned/archived and monitored for lag.

## 16. Performance and capacity

| Concern | Standard |
|---|---|
| Connection | Hyperdrive; transaction pooling; no session state |
| Pool saturation | < 70% at peak; alert at 80% |
| Hot table growth | Partition or archive before 100M rows |
| Bloat | Autovacuum tuned; monitor dead tuples |
| Slow queries | `pg_stat_statements`; top 20 reviewed monthly |
| Locks | Monitor long-running transactions; kill only with approval |
| Read replicas | Reporting/search only; lag budget 5 s; read-your-writes on primary |
| Cache | KV for reference data; invalidation by version/event |
| Batch writes | Attendance/marks in batches ≤ 500 rows per transaction |

## 17. Testing the database

| Test | Requirement |
|---|---|
| Migration from empty | Every PR |
| Migration from previous | Every PR |
| RLS cross-tenant | Every PR |
| Constraint/invariant | Unit + integration |
| Idempotency | Duplicate request/event |
| Concurrency | Two writers, optimistic lock conflict |
| Restore | Monthly for Tier 1 |

| Data reconciliation | Nightly job + alert |

## 18. Drizzle conventions

```ts
// services/student/src/infrastructure/db/schema.ts
import { pgSchema, uuid, text, date, timestamp, integer, index, uniqueIndex } from 'drizzle-orm/pg-core';

export const studentSchema = pgSchema('student');

export const students = studentSchema.table(
  'students',
  {
    id: uuid('id').primaryKey(),
    tenantId: uuid('tenant_id').notNull(),
    studentNumber: text('student_number').notNull(),
    status: text('status').notNull(),
    version: integer('version').notNull().default(1),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
    deletedAt: timestamp('deleted_at', { withTimezone: true }),
  },
  (t) => ({
    tenantNumber: uniqueIndex('uq_students_tenant_number').on(t.tenantId, t.studentNumber),
    tenantStatus: index('ix_students_tenant_status').on(t.tenantId, t.status),
  }),
);
```

Rules:

- Schema definitions live in `infrastructure/db/schema.ts`; domain never imports them.
- Column names are explicit snake_case; TS properties camelCase.
- Types inferred with `InferSelectModel`/`InferInsertModel`, never hand-written duplicates.
- Repositories map rows → domain entities; no Drizzle types leak into application/domain.
- Transactions use the `withTenant` helper (sets `app.tenant_id`).
- Migrations are generated, reviewed and committed.

## 19. Review checklist

- [ ] `tenant_id` on every table; RLS enabled/forced; index leads with tenant.
- [ ] PK UUIDv7; no natural key as PK.
- [ ] Money uses numeric + currency; no float.
- [ ] Timestamps are `timestamptz`; dates are `date`.
- [ ] Constraints encode invariants; FKs within schema; no cross-schema FK.
- [ ] Soft delete partial indexes; immutable financial/audit tables.
- [ ] Explicit columns; cursor pagination; query plan for hot paths.
- [ ] Migration expand/contract, tested, rollback documented.
- [ ] Outbox/inbox where events are published/consumed.
- [ ] Restricted fields encrypted; blind index for exact search.
- [ ] Data catalog updated (classification, retention, purpose).
- [ ] Cross-tenant tests added.
