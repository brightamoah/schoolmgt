# Core Database Schema (DDL)

> **Status:** Accepted · **Owner:** Data Platform · **Version:** 1.0
>
> Reference DDL for the tenancy, identity, authorization, academic, admissions and student services.
> It is intentionally explicit: production migrations are generated from Drizzle schemas and
> reviewed against these invariants. `uuid` values are UUIDv7 generated by the application.
>
> Conventions: see [Database conventions](database-conventions.md). All timestamps are UTC.

## 1. Schemas and extensions

```sql
create extension if not exists citext;
create extension if not exists pg_trgm;
create extension if not exists btree_gist;

create schema if not exists tenant;
create schema if not exists identity;
create schema if not exists authz;
create schema if not exists academic;
create schema if not exists admissions;
create schema if not exists student;
```

## 8. Row-level security

Apply to every table with `tenant_id`; `tenant.tenants` is keyed by `id`.

```sql
do $$
declare r record;
begin
  for r in
    select schemaname, tablename
    from pg_tables
    where schemaname in ('tenant','identity','authz','academic','admissions','student')
      and tablename <> 'permissions'
  loop
    execute format('alter table %I.%I enable row level security', r.schemaname, r.tablename);
    execute format('alter table %I.%I force row level security', r.schemaname, r.tablename);

    if r.schemaname = 'tenant' and r.tablename = 'tenants' then
      execute format(
        'create policy tenant_self on %I.%I using (id = current_setting(''app.tenant_id'', true)::uuid) with check (id = current_setting(''app.tenant_id'', true)::uuid)',
        r.schemaname, r.tablename);
    else
      execute format(
        'create policy tenant_isolation on %I.%I using (tenant_id = current_setting(''app.tenant_id'', true)::uuid) with check (tenant_id = current_setting(''app.tenant_id'', true)::uuid)',
        r.schemaname, r.tablename);
    end if;
  end loop;
end $$;
```

Exceptions and controls:

- `authz.permissions` is platform-level, read-only, contains no tenant data.
- The control-plane role (`tenant_provisioner`) has `BYPASSRLS` and is used only by the provisioning
  Workflow; every use is audited.
- Missing `app.tenant_id` must cause an error. Add a guard in the connection helper; optionally use
  `current_setting('app.tenant_id')` without `true` in critical policies to fail hard.

## 11. Data integrity notes

| Invariant | Enforcement |
|---|---|
| Tenant isolation | RLS + explicit predicate + cross-tenant tests |
| One active enrolment per learner/section/term | Partial unique index |
| Unique student number per institution | Unique constraint |
| Guardian link verified before access | `verified_at` + authorization policy |
| Offer acceptance capacity | Transaction + seat reservation (DO/DB) |
| No cross-tenant domain | Unique `domain` globally; tenant ownership verified |
| Sessions revocable | `revoked_at` + version; DO invalidation |
| Immutable issued documents | Separate tables/snapshots in finance/assessment |

This schema is the reference; per-service Drizzle definitions must match it, and migrations must be
reviewed against the invariants above.
